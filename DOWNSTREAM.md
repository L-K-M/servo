# Downstream changes

Every change `combray/0.N` carries on top of its upstream release: why Combray needs
it, how to check it, and when upstream makes it redundant. Update this list in the
same PR as the change: add an entry with each downstream change, and remove the entry
when an upstream merge drops the change. Each upstream merge reviews every entry (see
[AGENTS.md](AGENTS.md)). Describe changes through engine behavior and synthetic test
cases; never name a website.

| Change | Commits | Why | Check | Drop when |
|---|---|---|---|---|
| Downstream repository setup | `d65da5c839c`, `a5c85183440` | Removes upstream CI workflows, CODEOWNERS and dependabot, which can contact other projects; adds `AGENTS.md`, the README section and this file | `.github/workflows/`, `.github/CODEOWNERS` and `.github/dependabot.yml` stay absent after every upstream merge | Never |
| Embedder API: top-level document identity | `f860cdf98ec`, `f9cfe66cf42` | Combray's native bridge tags callbacks with the reporting document and evaluates scripts only in a still-active document; an evaluation that reaches a document after it was replaced or deactivated returns `DocumentNotFound` instead of running | Combray's Engine workflow (native builds and device checks) | Upstream offers an equivalent API and Combray has moved to it |
| Paint: log WebRender render errors | `70b288de85e` | A failed render silently left the previous frame on screen | None (logging only) | Upstream handles the result of `Renderer::render` |
| Net: persist profile state on request, atomically | `718bb542539`, `15b92fc4c9d` | Android kills apps without a clean exit, which lost cookies, HSTS and auth state; in-place writes could truncate profile files | Combray's Engine workflow (persistence device checks) | Upstream persists on demand and writes profile files atomically |
| DOM: `:has()` in `querySelector`, `matches` and `closest` | `97be6cb1fb5`, `02cfa0e180f`, `1b0b34350ed` | DOM queries with `:has()` threw; stylesheet `:has()` stays disabled until Servo wires relative invalidation | `./mach test-wpt --profile medium --headless tests/wpt/mozilla/tests/mozilla/has-selector-dom-queries.html tests/wpt/tests/css/selectors/` (the upstream `:has()` query tests pass) | Upstream enables `:has()` for DOM queries |
| Paint: chain input scrolls from fixed layers to the viewport | `4a294fff0ea`, `1a96dd8d50b` | Fixed-position descendants sit beside the viewport in the spatial tree, so an unconsumed wheel, touch pan or fling over a fixed layer (a closed drawer, a sticky bar) never scrolled the page | `cargo test --profile medium -p servo-paint-api --test compositor` (`test_scroll_tree_chain_from_fixed_drawer_to_viewport`, `test_touch_scroll_tree_chain_from_fixed_drawer_to_viewport`) | Upstream chains input scrolls from fixed layers to their document's viewport |
| Script: keep default page colors light until a page opts into dark | `b7687abc34c`, `546db2b2db1`, `bf8c0089364` | With a dark system appearance, pages without their own colors got pale default text on a white canvas; the root now gets a light color-scheme hint until metadata or an author style opts into dark, and rematches when metadata changes | `cargo test --profile medium -p servo --test webview test_dark_theme_keeps_unstyled_page_colors_light`; Combray's Engine workflow (painted-color device regression) | Upstream keeps unstyled pages light until they opt into a dark color scheme |
| WebDriver: listen on loopback only | `1f380c6b3fc` | The site check runs servoshell with WebDriver on a home network; `0.0.0.0` exposed it to the LAN | `cargo test --profile medium -p servo-webdriver-server --lib` (`listens_on_loopback_only`) | Upstream binds loopback |
| Deps: patched TLS and crypto crate releases | `f3df0020e53` | cargo-deny advisories against rustls 0.23.45, rustls-webpki 0.103.15, webpki-roots and webpki-root-certs 1.0.9, crypto-bigint 0.7.5 and ctutils 0.4.2 in v0.7.0's lockfile | `./mach test-tidy` reports none of these advisories | An upstream release locks these versions or newer (upstream main has `5abd89f8ca3` and `e78fc913f26`) |
| Backport: patched zstd crates | `a8980f6fc4a`, `e3145fe6141`, `957573976d4` (upstream `702613052bb`, `361b3b169a3`, `07b8ee4e091`) | cargo-deny advisories RUSTSEC-2026-0391, -0398, -0403 and -0410 against zstd 0.14.0, zstd-safe 8.0.0 and zstd-sys 2.1.0 in v0.7.0's lockfile; Servo decodes `zstd` content encoding with them | `./mach test-tidy` reports none of these advisories | The next upstream release that contains `702613052bb`, `361b3b169a3` and `07b8ee4e091` |
| Backport: flex layout reuse | `1ae5ce711d5`, `fceec0c6584` (upstream `b0c20e94ae2`, `f07470d3911`), test `d12858d1c8c` | In v0.7.0 each nested flex container laid out its items several times without reusing the result, so layout time doubled per nesting level and pages built from a few dozen nested flex containers froze | `./mach test-wpt --profile medium --headless tests/wpt/mozilla/tests/mozilla/flex-nested-column-layout.html tests/wpt/tests/css/css-flexbox/` | The next upstream release that contains `b0c20e94ae2` and `f07470d3911` |
| Backport: root pending timer callbacks | `25b6c23298c` (upstream `3ae0049380f`) | v0.7.0 can collect a pending `setTimeout` callback before it fires, and the script thread then crashes when it calls the timer | `./mach test-wpt --profile medium --headless tests/wpt/mozilla/tests/mozilla/pending-timer-crash.html` | The next upstream release that contains `3ae0049380f` |
| DOM: null prefix for the parsed foreign attribute `xmlns` | `e15fcd7b3cb` | html5ever 0.40.1 adjusts `xmlns` on `<svg>` and `<math>` to an empty prefix, so the attribute's name became `:xmlns`; libraries that read attribute names (`:` is a binding shorthand in some) then failed on every inline SVG | `./mach test-wpt --profile medium --headless tests/wpt/mozilla/tests/mozilla/parser-foreign-xmlns-attribute.html` | html5ever adjusts `xmlns` to a null prefix, or upstream Servo ignores empty parser prefixes |
| Script: `console.table` and `console.dirxml` | `7222136ddbb` | Both Console methods were missing from the IDL, so calling them threw `TypeError` and aborted the calling script; they now log their arguments at the log level, the fallback the Console standard allows | `./mach test-wpt --profile medium --headless tests/wpt/mozilla/tests/mozilla/console-table-dirxml.html tests/wpt/tests/console/` | Upstream implements both methods |
| Script: every PerformanceTiming name in `performance.measure()` | `9b12bd59e7f` | `measure()` threw `OperationError` for marks named `fetchStart`, `domainLookupStart`, `domainLookupEnd`, `connectStart`, `connectEnd`, `requestStart`, `responseStart` and `domLoading`, aborting scripts that measure from the start of the fetch; they now convert to the document's timestamps, or throw `InvalidAccessError` when Servo recorded none | `./mach test-wpt --profile medium --headless tests/wpt/mozilla/tests/mozilla/performance-measure-timing-names.html tests/wpt/tests/user-timing/` | Upstream converts every PerformanceTiming name |
